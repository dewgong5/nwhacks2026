# Design

## Context

`a` contains the latest demo-specific work, `main` is the remote default, and `afterhack` contains newer deployment/WebSocket-ticket changes. The branches diverge, and generated bytecode plus secret-bearing configuration complicate direct merges.

## Goals / Non-Goals

**Goals:** produce one traceable authoritative baseline while preserving useful behavior and commit attribution.

**Non-Goals:** broad cleanup or asserting that any branch is correct merely because it is newer.

## Decisions

1. **Use a reconciliation branch from the selected future default.** Do not mutate or delete source branches until acceptance.
2. **Build a behavior matrix before integration.** Compare simulation semantics, API/WebSocket contracts, frontend URLs, security controls, configuration, documentation, and generated files.
3. **Integrate bounded commits by concern.** Security/configuration, backend behavior, frontend contract, and documentation remain separately reviewable. Prefer cherry-pick or manual semantic integration over an opaque merge when the same files diverged.
4. **Treat `afterhack` ticketing as candidate code.** Remove raw-WebSocket fallback, verify origin/proxy assumptions, and do not inherit `allow_origins=["*"]` as approved security.
5. **Use a fixed acceptance matrix.** Run the existing build/lint/test/smoke commands and record expected known failures before quality cleanup.

## Risks / Trade-offs

- [Semantic regression hidden by clean merge] → contract/event comparisons and smoke tests.
- [Secret-bearing lines reintroduced] → scan each integration commit and preserve the secure configuration contract.
- [History manipulation harms collaborators] → no force push, rebase, or deletion without explicit approval.

## Migration Plan

Fetch refs; create read-only comparison; select target with user confirmation if implementation would change the default branch; create reconciliation branch; integrate concern-by-concern; run matrix; review diff; only then propose default-branch/remote actions. Rollback is deleting the new local integration branch before publication or reverting its bounded commits after publication.
